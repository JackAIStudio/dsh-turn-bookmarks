# dsh-turn-bookmarks (DSH 会话轮次收藏与对话内检索插件)

DSH Web GUI 原生 Turn Rail（轮次导航轨）深度赋能插件：**100% 融入官方原生轨道**，告别冗余并排的第二条尺子。

## 核心特性

- **清晰轮次标明（SSOT 单一事实源）**：基于官方原生刻度无障碍 `aria-label` 精准解析 `turn` 轮次编号，无论长对话虚拟化如何滚动，绝对不发生任何错位！
- **悬停卡片原生注入**：官方预览卡悬停时，自动注入「第 N 轮」徽章、一键收藏（⭐）及一键复制（📋）问答正文，不篡改官方原生定位与渲染流程。
- **量尺金色微光高亮**：收藏的轮次在右侧官方量尺上呈现醒目的金色加宽刻度条与粒子光晕，一眼纵览整场对话关键节点。
- **全会话内即时检索**：
  - 点击右上角搜索图标展开搜索栏（纯鼠标操作，**不占用任何全局快捷键**，不干扰正文输入；面板内点 `×` 收起）；
  - 实时统计匹配轮次（如 `1/4 轮`），并在量尺上高亮所有匹配刻度（亮蓝/青色微光）；
  - 在搜索框内支持 `Enter` / `Shift+Enter` 或 `▲` / `▼` 按钮在匹配轮次间顺畅跳转（仅在搜索框聚焦时生效，属局部按键，不劫持全局键盘）；
  - 跳转时触发官方原生 `click` 导航，自动支持「加载更早」历史回溯，并对目标消息气泡做视觉聚焦微光提示。
  - 搜索入口始终只有一份：DSH 热重建插件包会重新执行 `apply`，插件在挂载时先停掉上一个实例、给残留搜索栏打 stale 标记（CSS 隐藏），旧实例的 tick 与 150ms 防抖回调发现自己是孤儿时也会自行退场。窗口刷新或插件反复重建都不会再叠出一排放大镜。
  - 搜索栏插在会话头的 tabs 行里，而宿主给整行设了 `-webkit-app-region: drag`（窗口拖拽区），鼠标按下会被系统拿去拖窗口，表现为「图标在、hover 和 click 都没反应」。插件在自己的容器上显式声明 `no-drag`，不依赖宿主是否补这一条。
- **双轨书签导航（双轨架构）**：右侧官方原生轨保留全场轮次宏观总览，收藏轮次呈现琥珀金高亮；左侧另设**专属书签轨**，仅列出已收藏轮次（`★ T1` / `★ T2` 紧凑列），点击落点与原生轨完全分离，**彻底杜绝误点**。
- **跨会话持久化**：本地 `localStorage` + 后端 JSON 存储双重持久化，按 `sessionId` 严格隔离，数据永不丢失。
  - 存储位置跟随**当前实例的 harness home**（与 DSH 核心同一套规则：`DSH_HOME` 优先，否则 `~/.dsh`）：`<DSH_HOME>/turn-bookmarks.json`。同一台机器上并存多个实例（如 `dsh web --port 3080` 与 JackDSH 桌面端）时，各写各的，互不混用。
  - 旧版本曾把路径写死为 `~/.dsh`；升级后首次启动会把"会话确实属于本 home"的条目自动搬回，其余实例的收藏原样保留（幂等）。
- **原生明暗主题自适应**：无缝跟随 DSH Web 浅色与深色模式。
- **点 ✏️ 直接分叉，并把这一轮的输入带进新会话**：用户消息行上的 ✏️ 不再就地展开编辑器，而是按官方「在新对话中分支」的方式从该轮**之前**的分界点 fork 出新会话，然后把这一轮原来的提示词和附件放进新会话的官方输入框，**不自动发送**。
  - 提示词里如果有会话引用，会还原成输入框里的会话胶囊，而不是一长串 `@[标题](dsh-session:…)` 裸文本。
  - 图片和文件都通过官方 `conversation.createDrafts` + 输入框 `addAttachments` 挂上去，落进输入框就是原生附件卡，可以继续加、删、拖；「加不了新附件」的问题自然消失。
  - 模型、思考程度、权限一律交给输入框自己的选择器。插件不再切换模型、不再代发 `/permission`，也不替你按下发送。
  - 图片走官方 `session.readAttachment` 读回字节；原样文件走宿主路由 `/dsh-turn-bookmarks/attachment` 从 `<DSH_HOME>/attachments/v1` 读回字节。读不出来的附件会列出来让你手动补。
  - 宿主侧路由：`/dsh-turn-bookmarks/turn-content`（某一轮的文本 + 附件引用）与 `/dsh-turn-bookmarks/attachment`（按 attachmentId 读取字节，48 MiB 上限）。
- **每轮结果旁标出实际使用的模型**：来自该轮的 `request/header`，重新打开会话也一致；它只是显示，不参与分支流程。
  - 客户端插件是宿主合包提供的，改完 `client.js` 需要**完全退出并重启应用**才会装载新代码；只刷新窗口仍会跑旧包。

## 性能约束（2026-11-06 修复）

原生轨的 `.mark` 按钮归 React 受控渲染。`tick` 每 500 ms 都会重算这些按钮的状态，而 `classList.add` / `classList.remove` / `dataset` 赋值**即便写入相同值，也会派发 mutation**，唤醒宿主的 MutationObserver，再排一轮 enhance —— 大会话里表现为渲染进程常驻 30–40% CPU、整窗发顿。因此这里的写入一律先比较再写：

- `data-dsh-turn` 只在编号变化时写；
- `dsh-tb-mark-starred` / `dsh-tb-pos-starred` / `dsh-tb-mark-matched` / `dsh-tb-mark-current-match` 用 `classList.contains` 比对后 `toggle`；
- `.dsh-tb-turn-model` 的 `textContent` 与 `title` 仅在变化时写。

新增任何周期性写 DOM 的代码，都要遵守同一条规则。
